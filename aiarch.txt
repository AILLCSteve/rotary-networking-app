CURRENT SYSTEM DESIGN: 5-Layer Parallel Processing Pipeline
------------------------------------------------------------

┌─────────────────────────────────────────────────────────────────────────┐
│                          EXECUTION TIMELINE                              │
├─────────────────────────────────────────────────────────────────────────┤
│ 0s ────── 45s ────── 135s ────── 180s ────── 210s ────── 210s          │
│  │         │           │           │           │           │            │
│  L1        L1          L2          L2          L3          L4          │
│ Start     End        Start       End        Start       Start          │
│                                                                          │
│ [════════ Layer 1: 8 parallel calls ═══════]                           │
│            [════════════════ Layer 2: 5 agents ═══════════════]        │
│                              [═══ L3 ═══][═ L4 ═]                      │
│                                                                          │
│ Total Pipeline Time: ~210 seconds (3.5 minutes average)                │
└─────────────────────────────────────────────────────────────────────────┘

LAYER BREAKDOWN:
----------------
Layer 1: Parallel Data Gathering
  - 8 simultaneous API calls
  - Mix of web search simulation + AI analysis
  - Timeout: 45 seconds
  - Execution: Promise.all()
  - Failure handling: Graceful degradation (continues with partial data)

Layer 2: Multi-Agent Analysis
  - 5 specialized AI agents
  - Each runs independently with same input data (Layer 1 output)
  - Timeout: 90 seconds
  - Execution: Promise.all()
  - Failure handling: Continues with available agents

Layer 3: Master Synthesis
  - Single AI call
  - Combines all Layer 2 outputs
  - Resolves conflicts, identifies consensus
  - Timeout: 45 seconds
  - Failure handling: Throws error (critical stage)

Layer 4: Quality Control
  - Single AI call
  - Fact-checks Layer 3 against Layer 1 raw data
  - Timeout: 30 seconds
  - Failure handling: Non-blocking (returns unchecked synthesis)

Layer 5: Scoring & Visualization
  - Client-side JavaScript computations
  - No AI calls
  - Instant execution
  - Failure handling: N/A (pure math)

KEY ARCHITECTURAL DECISIONS:
----------------------------
1. Parallel > Sequential: Layers 1 & 2 use Promise.all() for speed
2. Agent Independence: Each agent sees same data, prevents cascading errors
3. Synthesis Last: All perspectives gathered before combining
4. Fact-Check Final: Validates against raw source data
5. Client-Side Scoring: Reduces server load, enables real-time interaction

LAYER 5: SCORING & VISUALIZATION
----------------------------------
Function: layer5_calculateEnhancedScore(agentOutputs, synthesis, qualityControl)
Location: nexus-v2.js:516-607
Execution: JavaScript (client-side capable, but runs server-side)
Model: None (pure computation)

Scoring Formula:
----------------
1. Extract dimension scores from agents:
   - strategic_synergy (from Agent A)
   - tactical_value (from Agent E)
   - innovation_potential (from Agent B)
   - risk_compatibility (100 - Agent C risk score)
   - network_effects (from Agent D)
   - temporal_urgency (calculated heuristic)

2. Calculate base score (weighted average):
   baseScore =
     (strategic_synergy * 0.25) +
     (tactical_value * 0.20) +
     (innovation_potential * 0.20) +
     (risk_compatibility * 0.15) +
     (network_effects * 0.15) +
     (temporal_urgency * 0.05)

3. Calculate uniqueness coefficient (entropy boost):
   uniqueness =
     (unexpected_synergies * 0.05) +
     (unique_insights * 0.05) +
     (innovation_bonus: if score > 80, +0.1) +
     (network_multipliers * 0.03)

   Capped at 0.5 (50% max boost)

4. Apply entropy-based differentiation:
   entropyBoostedScore = baseScore * (1 + uniqueness)

5. Calculate agent consensus weight:
   avgConfidence = mean(all agent confidence scores)
   consensusWeight = (avgConfidence / 100) ^ 1.5

6. Final score:
   finalScore = min(entropyBoostedScore * consensusWeight, 100)

7. Grade assignment:
   90+ = A+, 85-89 = A, 80-84 = A-, 75-79 = B+, etc.

SCORING DIMENSIONS EXPLAINED:
------------------------------
Strategic Synergy (25%): Long-term business model alignment
Tactical Value (20%): Immediate exchangeable value
Innovation Potential (20%): Creative collaboration opportunities
Risk/Compatibility (15%): Cultural fit, low conflict (inverse risk)
Network Effects (15%): Connection multiplication, introductions
Temporal Urgency (5%): Why NOW matters (market timing)

ENTROPY BOOST RATIONALE:
-------------------------
Problem: Without entropy boost, common patterns score high
Example: "Marketing agency + Tech company" = common (slight penalty)
         "Construction + AI startup" = rare (entropy boost)

The uniqueness coefficient amplifies rare, high-value combinations
while slightly dampening common patterns. This creates wider score
distribution and makes exceptional matches truly stand out.

4. SCORING & DIFFERENTIATION ALGORITHMS
================================================================================

CURRENT ALGORITHM ANALYSIS:
---------------------------
The scoring system uses three key mechanisms to prevent score bunching:

1. WEIGHTED MULTI-DIMENSIONAL SCORING
   Instead of single score, 6 dimensions weighted:
   - Prevents single factor dominating
   - Captures complexity of human relationships
   - Allows trade-offs (high risk but high innovation = still good match)

2. ENTROPY-BASED UNIQUENESS BOOST
   Rare combinations get amplified:
   Formula: finalScore = baseScore * (1 + uniquenessCoefficient)

   Example:
   - Common match: Marketing + Sales (uniqueness = 0.05) → 70 * 1.05 = 73.5
   - Rare match: Construction + AI (uniqueness = 0.35) → 70 * 1.35 = 94.5

   This creates natural spreading of scores across full 40-95 range.

3. CONSENSUS WEIGHTING
   Agent agreement matters:
   - 5/5 agents agree: consensusWeight = 1.0 (100% confidence)
   - 3/5 agents agree: consensusWeight = 0.6^1.5 = 0.46 (46% confidence)

   This penalizes uncertain matches, rewards clear winners.

MATHEMATICAL PROPERTIES:
------------------------
Distribution Analysis (Theoretical):
- Min Score: 40 (all dimensions 40, no uniqueness, low consensus)
- Max Score: 100 (capped)
- Mean (Expected): ~72
- Std Dev (Expected): ~18
- Shape: Right-skewed normal (most 60-80, tail extends to 95+)

This creates three natural clustering bands:
- 40-65: Weak matches (proceed with caution)
- 66-80: Good matches (worthwhile connections)
- 81-100: Exceptional matches (high priority)

COMPARISON TO V1:
-----------------
V1 Algorithm:
  - Simple additive scoring (6 categories, each 0-20 points)
  - No uniqueness boost
  - No consensus weighting
  - Result: Scores bunched 65-78 (narrow range)

V2 Algorithm:
  - Weighted multi-dimensional (6 dimensions, varying weights)
  - Entropy-based uniqueness boost (up to 50% increase)
  - Consensus weighting (exponential)
  - Result: Scores spread 40-95 (wide range)

ALGORITHM PARAMETERS (Tunable):
--------------------------------
These values can be adjusted for different outcomes:

Dimension Weights:
  strategic_synergy: 0.25  (increase to prioritize long-term value)
  tactical_value: 0.20     (increase for immediate-value focus)
  innovation_potential: 0.20 (increase for creative emphasis)
  risk_compatibility: 0.15  (increase for cautious matching)
  network_effects: 0.15     (increase for connection-focused)
  temporal_urgency: 0.05    (increase for time-sensitive)

Entropy Boost Factors:
  unexpected_synergies: 0.05 per synergy (increase to reward creativity)
  unique_insights: 0.05 per insight (increase to value unique findings)
  innovation_bonus: 0.10 if score > 80 (adjust threshold/bonus)
  network_multipliers: 0.03 per multiplier (increase to prioritize network)
  max_uniqueness: 0.5 (increase to allow larger boosts, up to 1.0 = 100%)

Consensus Weight Exponent: 1.5
  - Lower (1.0): Linear weighting (less penalty for disagreement)
  - Higher (2.0): Exponential weighting (severe penalty for disagreement)

ALTERNATIVE ALGORITHMS TO CONSIDER:
------------------------------------

Option 1: Machine Learning Scoring Model
  - Train on historical match data + user feedback
  - Features: All agent scores, dimension scores, profile attributes
  - Target: User rating (1-5 stars) or success binary (met/didn't meet)
  - Model: Gradient Boosting (XGBoost, LightGBM)
  - Pros: Learns from actual outcomes, adaptive
  - Cons: Requires training data, black box

Option 2: Graph-Based Network Scoring
  - Model all members as nodes, potential connections as edges
  - Edge weight = match quality score
  - Use PageRank-style algorithm to identify high-value connections
  - Pros: Considers network effects, finds optimal connection paths
  - Cons: Computationally expensive, requires all-pairs analysis

Option 3: Bayesian Confidence Intervals
  - Each dimension score = probability distribution (not point estimate)
  - Final score = posterior probability of "high-value match"
  - Uncertainty captured in confidence intervals
  - Pros: Principled uncertainty quantification
  - Cons: More complex implementation, requires prior specification

Option 4: Multi-Objective Optimization
  - Treat 6 dimensions as separate objectives
  - Find Pareto frontier (no dimension can improve without hurting another)
  - Present user with top N Pareto-optimal matches
  - Pros: Preserves trade-offs, no arbitrary weighting
  - Cons: Harder to rank, may overwhelm user with choices

RECOMMENDATION: Start with current algorithm, collect user feedback data,
                then train ML model (Option 1) as V3 enhancement.

CURRENT PERFORMANCE PROFILE:
-----------------------------
Stage                    | Time (avg) | Time (max) | % Total
-------------------------|------------|------------|--------
Layer 1 (8 parallel)     | 35s        | 45s        | 20%
Layer 2 (5 agents)       | 75s        | 90s        | 43%
Layer 3 (synthesis)      | 40s        | 45s        | 23%
Layer 4 (fact-check)     | 25s        | 30s        | 14%
Layer 5 (scoring)        | <1s        | <1s        | <1%
-------------------------|------------|------------|--------
Total Pipeline           | 175s       | 210s       | 100%
                         (2.9 min)   (3.5 min)

BOTTLENECK ANALYSIS:
--------------------
1. Layer 2 is the bottleneck (43% of total time)
   - 5 agents @ 1000 tokens each = 5000 tokens
   - GPT-4o processing time per call: ~15 seconds
   - Parallel execution means longest agent determines total time
   - Worst case: All 5 agents take full 90s timeout

2. Layer 3 synthesis is secondary bottleneck (23%)
   - Must wait for Layer 2 to complete
   - Single large call (2000 tokens)
   - Cannot be parallelized (needs all agent outputs)

3. Layer 1 is relatively fast (20%)
   - Already parallelized well
   - Using cheaper GPT-4o-mini model
   - Could be optimized further with web APIs

OPTIMIZATION STRATEGIES:
------------------------

Strategy A: Reduce Layer 2 Time (Target: -30 seconds)
  1. Lower max_tokens for agents with predictable output length
     - Agent C (risk) typically outputs 600 tokens → reduce to 700 max
     - Agent E (tactical) typically outputs 700 tokens → reduce to 800 max
     - Savings: ~5-10 seconds

  2. Use GPT-3.5-turbo for Agent E (tactical)
     - Tactical planning is simpler task
     - GPT-3.5-turbo is 10x faster, 1/20th cost
     - Savings: ~10 seconds

  3. Implement agent caching
     - If same member pair analyzed within 24 hours, return cached result
     - Hit rate (estimated): 15-20% for events with 50+ members
     - Savings: 175 seconds on cache hit

Strategy B: Parallelize Layer 3 & 4 (Target: -20 seconds)
  - Layer 3 generates synthesis
  - Layer 4 fact-checks synthesis
  - These are currently sequential
  - Could run "fast draft synthesis" + "full synthesis" in parallel
  - Then fact-check only the full synthesis
  - Savings: ~20 seconds

Strategy C: Progressive Disclosure (Target: UX improvement)
  - Don't wait for full pipeline to complete
  - Show Layer 1 results immediately (35s)
  - Show Layer 2 agent cards as they complete (75s)
  - Show final score after Layer 3 (115s)
  - Layer 4 fact-checking runs in background
  - User sees results 60 seconds faster

Strategy D: Model Optimization (Target: -15 seconds + cost reduction)
  - Replace GPT-4o with Claude 3.5 Sonnet for Layer 2 Agent B
    (Claude often faster + cheaper for creative tasks)
  - Replace GPT-4o with GPT-4o-mini for Layer 4 fact-checking
    (Fact-checking is pattern matching, not complex reasoning)
  - Estimated savings: 15 seconds, $0.10 per match

COST ANALYSIS:
--------------
Current Cost per Match:
  Layer 1 (8 calls @ GPT-4o-mini):  $0.02
  Layer 2 (5 calls @ GPT-4o):       $0.20
  Layer 3 (1 call @ GPT-4o):        $0.08

Cost Optimization Targets:

SCALABILITY ANALYSIS:
---------------------
Current System:
  - Max concurrent requests: Limited by OpenAI rate limits
  - GPT-4o: 10,000 TPM (tokens per minute)
  - Our pipeline: ~12,200 tokens per match
  - Max throughput: ~0.82 matches per minute (49 matches/hour)

For event with 100 members:
  - All possible pairs: 100 * 99 / 2 = 4,950 pairs
  - Time to generate all: 4,950 / 0.82 = 6,036 minutes = 100.6 hours

Clearly not scalable for full all-pairs generation.

Solution: Smart Pre-filtering
  - Use V1 lightweight scoring to filter to top 20 candidates per member
  - Then run NEXUS V2 on only those 20 pairs per member
  - Total matches: 100 * 20 = 2,000 pairs
  - Time to generate: 2,000 / 0.82 = 2,439 minutes = 40.6 hours
  - Still too slow for real-time

Better Solution: Batch Processing Overnight
  - Generate NEXUS V2 matches asynchronously
  - Queue system (Redis + Bull or similar)
  - Process overnight before event
  - Members see results next morning

Best Solution: Progressive NEXUS V2
  - Start with V1 scores for all members (fast)
  - User clicks "Get NEXUS V2 Analysis" on interesting matches
  - On-demand generation (2-3 minutes wait)
  - Cache result for future viewers

8. RESEARCH AREAS FOR IMPROVEMENT
================================================================================

RESEARCH QUESTION 1: What is the optimal number of agents?
-----------------------------------------------------------
Current: 5 agents
Hypothesis: More agents = better diversity, but diminishing returns

Experiment:
  - Test with 3, 5, 7, 10 agents
  - Measure: Score variance, user satisfaction, processing time, cost
  - Find inflection point where marginal benefit = marginal cost

Expected Findings:
  - 3 agents: Too few perspectives, missing insights
  - 5 agents: Good balance (current)
  - 7 agents: Slight improvement, significantly higher cost
  - 10 agents: No improvement, redundant perspectives

Recommendation: Test at next major event, collect data

RESEARCH QUESTION 2: Do different models produce meaningfully different results?
--------------------------------------------------------------------------------
Current: All GPT-4o (except Layer 1)
Hypothesis: Claude and GPT-4o have different strengths

Experiment:
  - Agent A: GPT-4o vs Claude 3.5 Sonnet
  - Agent B: GPT-4o vs Claude 3.5 Sonnet (creative agent, Claude might excel)
  - Agent C: GPT-4o vs GPT-4o-mini (risk is pattern matching, simpler)
  - Measure: Inter-model agreement, user preference, cost

Expected Findings:
  - Claude better for creative (Agent B)
  - GPT-4o better for structured analysis (Agent A)
  - GPT-4o-mini sufficient for risk (Agent C)

Recommendation: Run A/B test with 100 matches

RESEARCH QUESTION 3: What is the ideal temperature for each agent?
-------------------------------------------------------------------
Current: Temperature varies by agent (0.4 to 0.9)
Hypothesis: Temperature significantly affects output quality

Experiment:
  - For each agent, test temps: 0.3, 0.5, 0.7, 0.9
  - Measure: Score consistency (same input → same output?), user satisfaction
  - Optimal temp balances creativity and consistency

Expected Findings:
  - Lower temp (0.3-0.5): More consistent, less creative
  - Higher temp (0.7-0.9): More creative, less consistent
  - Optimal varies by agent role

Recommendation: Grid search optimization

RESEARCH QUESTION 4: How important is fact-checking (Layer 4)?
---------------------------------------------------------------
Current: Layer 4 removes ~5-10% of claims on average
Hypothesis: Users trust verified info more, but don't notice removal

Experiment:
  - A/B test: With Layer 4 vs Without Layer 4
  - Measure: User trust ratings, time spent reading, connection follow-through
  - Cost-benefit: Is 30s + $0.08 worth it?

Expected Findings:
  - Users don't consciously notice difference
  - But implicit trust higher with fact-checking
  - Fact-checking prevents embarrassing hallucinations

Recommendation: Keep Layer 4, but consider making it async (non-blocking)

RESEARCH QUESTION 5: What scoring algorithm maximizes user satisfaction?
-------------------------------------------------------------------------
Current: Entropy-based scoring with consensus weighting
Hypothesis: Different users prefer different scoring approaches

Experiment:
  - Compare 3 scoring algorithms:
    A. Current (entropy-based)
    B. Simple weighted average (no entropy)
    C. Machine learning model (trained on feedback)
  - Measure: User satisfaction, connection rate, perceived accuracy
  - Segment by user type (risk-averse vs risk-seeking)

Expected Findings:
  - Risk-averse users prefer simple weighted average (predictable)
  - Risk-seeking users prefer entropy-based (rewards uniqueness)
  - ML model best overall after sufficient training data

Recommendation: Personalized scoring algorithm based on user profile

RESEARCH QUESTION 6: Does synthesis improve upon raw agent outputs?
--------------------------------------------------------------------
Current: Layer 3 synthesizes all agent outputs into narrative
Hypothesis: Synthesis adds value, but users may prefer raw agent cards

Experiment:
  - A/B test: Synthesis vs Raw Agent Outputs
  - Measure: Comprehension, decision time, satisfaction
  - Maybe both are useful (synthesis for quick scan, agents for deep dive)

Expected Findings:
  - Synthesis better for quick decisions
  - Raw agents better for thorough analysis
  - Ideal UI shows both (synthesis first, agents collapsible)

Recommendation: Keep both, test different presentation orders

9. ALTERNATIVE APPROACHES TO CONSIDER
================================================================================

ALTERNATIVE 1: Sequential Refinement (Instead of Parallel Agents)
------------------------------------------------------------------
Current: 5 agents run in parallel, independently

Alternative: Agents run sequentially, each refining previous output
  1. Agent A: Initial analysis
  2. Agent B: Builds on Agent A's output, adds creativity
  3. Agent C: Reviews A+B, adds risk assessment
  4. Agent D: Reviews A+B+C, adds long-term strategy
  5. Agent E: Reviews all, creates tactical plan

Pros:
  - Each agent informed by previous insights
  - Builds coherent narrative naturally
  - May need less synthesis (Layer 3)

Cons:
  - Sequential = much slower (5x longer?)
  - Cascade errors (if Agent A wrong, all others wrong)
  - Groupthink (agents influenced by previous outputs)

Verdict: Parallel is better. Speed and diversity outweigh coherence.

ALTERNATIVE 2: Specialized Models per Task (Instead of GPT-4o for All)
-----------------------------------------------------------------------
Current: GPT-4o for most tasks (Layer 2, 3, 4)

Alternative: Use best model for each specific task
  - Layer 2 Agent A (analysis): GPT-4o
  - Layer 2 Agent B (creativity): Claude 3.5 Sonnet
  - Layer 2 Agent C (risk): GPT-4o-mini (pattern matching)
  - Layer 2 Agent D (strategy): GPT-4o
  - Layer 2 Agent E (tactics): GPT-3.5-turbo
  - Layer 3 (synthesis): Claude 3 Opus (superior synthesis)
  - Layer 4 (fact-check): GPT-4o-mini

Pros:
  - Optimal model for each task
  - Cost reduction (cheaper models where appropriate)
  - Potentially higher quality outputs

Cons:
  - More complex infrastructure
  - Different APIs (OpenAI, Anthropic)
  - Harder to maintain
  - Model-specific quirks/bugs

Verdict: Worth experimenting with. Start with Agent B (Claude) and measure impact.

ALTERNATIVE 3: Retrieval-Augmented Generation (RAG) for Layer 1
----------------------------------------------------------------
Current: Layer 1 simulates web search with GPT-4o-mini knowledge

Alternative: Use RAG with vector database
  - Pre-index industry reports, news articles, partnership case studies
  - Layer 1 retrieves relevant documents
  - Layer 2 agents get actual sources, not AI-generated summaries

Pros:
  - More accurate (real data, not hallucinated)
  - Citable sources (increase trust)
  - Potentially faster (vector search is fast)

Cons:
  - Requires large document corpus
  - Need to maintain/update index
  - Infrastructure cost (Pinecone, Weaviate, etc.)

Verdict: Excellent long-term enhancement. Requires significant setup.

ALTERNATIVE 4: Prompt Chaining with Smaller, Faster Models
-----------------------------------------------------------
Current: Large prompts to GPT-4o with all context

Alternative: Chain of smaller, focused prompts with GPT-3.5-turbo
  - Prompt 1: Extract key facts from profile
  - Prompt 2: Identify potential synergies based on facts
  - Prompt 3: Generate opportunities based on synergies
  - Prompt 4: Risk assessment
  - Prompt 5: Synthesize all

Pros:
  - Cheaper (GPT-3.5-turbo 20x cheaper)
  - Potentially faster (smaller, parallel calls)
  - More modular (easier to test/optimize each step)

Cons:
  - More API calls (latency overhead)
  - Context loss between steps
  - May need more tokens total (repeated context)

Verdict: Interesting for "NEXUS V2 Lite" (fast mode). Not for premium analysis.

ALTERNATIVE 5: Human-in-the-Loop Verification
----------------------------------------------
Current: Fully automated pipeline

Alternative: Human reviews synthesis before presenting to user
  - AI generates draft
  - Human expert (Rotary admin) reviews/edits
  - Human approves or sends back for revision
  - User sees human-verified analysis

Pros:
  - Highest quality
  - No hallucinations make it to user
  - Human judgment on nuance

Cons:
  - Not scalable (requires human labor)
  - Slow (human bottleneck)
  - Expensive (labor cost)

Verdict: Use for high-stakes matches only (VIPs, board members). Not general use.
